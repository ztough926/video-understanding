# video-understanding

> 把一段视频 / GIF 压成**几张「大模型读得清」的关键帧总览图**，让模型按时间顺序"看完"整个视频，再输出对它的完整理解。

不是"看视频"，是"看画面变化后的完整呈现帧"——丢掉停着不动的重复帧，只保留画面真正变了的那一刻，避免往模型嘴里塞几百张一模一样的图。

> [!IMPORTANT]
> **本工具必须配合「多模态大模型」使用。**
> 它自己不做任何识别——**只负责把视频压缩成几张清晰可读的关键帧图**，真正的"看懂"由具备视觉能力的多模态大模型完成。
> 换句话说：**不接多模态模型，它产出的只是一堆图片；接上多模态模型，它才是一个视频理解工具。**
> 拿它当"视频转文字"命令行工具、配纯文本模型跑、或期望它直接吐出结论，都属于误用。

## 为什么要它

给大模型看视频，直接抽帧有两个死穴：

1. **帧太多。** 一段 3 分钟的视频有 5000+ 帧，全喂进去既贵又没用——绝大部分帧长得一模一样。
2. **帧太糊。** 把几百帧拼成一张巨图，图是够大了，但读图工具会把整张图压缩到长边约 1568px 再交给模型，**每格只剩一两百像素**，字幕和注释全糊成一团。

这个工具同时解决这两件事：**只选"画面真的变了"的帧**，并且**宁可多出几张图，也不往一张里塞满小格**。

## 怎么配合多模态大模型用

**这是一个「前处理」工具，不是「理解」工具。** 它把一段视频变成多模态大模型**能读懂、读得清**的输入，理解本身由模型完成。

```
   视频 / GIF
       │
       ▼
┌──────────────────┐
│  本工具（前处理）  │   逐帧差异检测 → 抽关键帧 → 拼成几张清晰总览图
│  纯图像算法       │   全程不调用任何模型，不"识别"任何内容
└──────────────────┘
       │
       ▼
   overview.jpg × N  +  keyframes.json
       │
       ▼
┌──────────────────┐
│ 多模态大模型（理解）│   读总览图 → 读画面上的文字 → 需要细节时读单帧
│  不限定厂商的模型  │   → 输出对这段视频的完整理解
└──────────────────┘
       │
       ▼
   自然语言描述（画面 + 文字 + 传达的信息）
```

两条分工必须说清楚：

| 环节 | 谁来做 | 做什么 |
| --- | --- | --- |
| **压缩与呈现** | **本工具** | 挑出画面真正变化的那几帧，排成时序总览图，保证每格里的文字在模型眼里还能看清 |
| **看懂与表达** | **多模态大模型** | 识别场景、主体、动作、光线、氛围，读出画面上的文字，综合成一段描述 |

所以：

- **它对模型的要求是「看得见图」**——纯文本模型无法使用本工具的产出。
- **它的参数是在为"模型的眼睛"调优**：`--sheet-max-cells`、`--cols`、`--sheet-width` 这三个旋钮的真实目的，是让每格在模型眼里保持足够像素（见下一节），而不是为了让人看得舒服。
- **它对模型的态度是"喂少而精"**：宁可用 3 张 12 格的图，也不给 1 张塞 40 格的巨图——因为后者模型看不清，成本还更高。
- **它自己不下结论**：脚本输出只有图和 JSON，没有任何"这是什么视频"的判断。所有语义结论都出自模型。

> 在支持视觉输入的 AI Agent 环境里，本仓库还附带一份 `SKILL.md`，把「抽帧 → 逐张读图 → 补读单帧 → 输出理解」整条链路固化成可自动调用的技能，详见 [作为 AI Agent Skill 使用](#作为-ai-agent-skill-使用)。

## 核心特性

| 特性 | 说明 |
| --- | --- |
| **为多模态大模型定制** | 参数、输出格式、分张策略全部围绕"让模型的『眼睛』看清"来设计；**产出即多模态模型的输入**，配合任意具备视觉能力的多模态大模型使用 |
| **智能抽帧** | 逐帧比较画面差异，只保留实质变化的帧；自动识别噪声底噪，静止画面不会被噪点骗出一堆废帧 |
| **自适应阈值** | 阈值 = 画面差异中位数（≈ 底噪）× 灵敏度倍数，并夹在 `0.008 ~ 0.08` 区间，**无需手动调参** |
| **双角度差异检测** | 全局平均差异（抓转场、换色）+ 8×8 分块最剧烈差异（抓角落小动作），取较大值 |
| **"等它变完"选帧** | 画面变化时不急着选，等动画结束后稳定下来的帧才入选——避免抽到元素还没出现/已经消失的空白中间态 |
| **自动分张** | 帧多时按时间顺序切成多张总览图，每张格数尽量平均，**每张清晰度一致** |
| **无元数据条** | 图面只有画面网格 + 每格下方 `#序号 时间戳`，尺寸/时长/帧率一律不占图面高度，全部放进 JSON |
| **GIF 支持** | 短视频 GIF 同样处理，≤8 帧的 GIF 全部保留 |
| **可当库用** | 既能命令行调用，也能 `import` 当模块用 |

## 效果：清晰度是由「每张几格」决定的

这是本工具最核心的一条设计约束，**也是「为什么必须配合多模态大模型」的直接后果**——它调的不是给人看的图，是给模型看的图。

多模态大模型的视觉编码器会把每张图**整体压缩到长边约 1080~1568px** 再送进来。所以：

> **每格能分到多少像素，只取决于「这张图里有多少格」，跟你把图做多大基本无关。**

实测同一段 4 分 42 秒讲解视频（1920×1080，78 个关键帧）：

| 配置 | 每格在模型眼里 | 结果 |
| --- | --- | --- |
| 12 格/张 · 3 列 · 1600px（**推荐默认**） | ~380px | 画面里的小字、字幕全可读 ✅ |
| 16 格/张 · 4 列 · 2400px | ~350px | 可读，接近上限 |
| 24 格/张 · 4 列 · 2400px | ~270px | 正文可读，小字吃紧，不推荐 |
| 40 格塞一张 · 6 列 · 9600px | ~180px | 糊，只剩版式和配色；且 9597px **直接被读图工具拒收** ❌ |

**三条硬规则：**

- **每张 ≤ 12 格（最多 16）** —— 要覆盖更多帧就多出几张图，不要往一张里塞
- **列数 ≤ 4** —— 要覆盖更多帧就增加行数，不要增加列数
- **图宽 ≤ 2400px** —— 超过约 8000px 直接拒收，1600 是"安全 + 够清"的落点

> 脚本默认 `--sheet-width 9600` 是为"人放大到 100% 看"设计的，出来的 9597×6323 图模型会直接拒收。**给模型读时必须显式降档。**

## 快速开始

### 命令行

**给大模型读的推荐档位**（务必显式传这三个参数）：

```bash
python scripts/extract_keyframes.py "video.mp4" \
  -o "out/my_video" \
  --cols 3 --sheet-max-cells 12 --sheet-width 1600 \
  -q --json
```

- `-o` 指定输出目录。**不加 `-o` 会把 `<视频名>_keyframes/` 建在视频旁边**，注意别污染原始素材目录。
- 路径含空格 / 中文一律加引号。
- `--json` 只吐一行 JSON，方便程序消费。

**只看总览图、不留单帧**：

```bash
python scripts/extract_keyframes.py video.mp4 --sheet-only
```

**一次处理多个文件**（`-o` 会失效，各自输出到 `<名>_keyframes/`，建议逐个跑）：

```bash
python scripts/extract_keyframes.py a.mp4 b.gif --json
```

### 当模块用

```python
from extract_keyframes import extract_keyframes

meta = extract_keyframes("demo.mp4", sheet_only=True)

print(meta["width"], meta["height"], meta["duration"])   # 原尺寸 / 总时长（秒）
print(meta["overview"])                                   # 首张总览图路径
print(meta["overviews"])                                  # 全部总览图路径列表
print(meta["keyframes"][0]["time"])                       # 第 1 帧时间戳
```

## 输出结构

```
out/my_video/
├── overview.jpg              ← 关键帧总览图（先读这张）
│   （帧多时自动分张：overview_01.jpg、overview_02.jpg …）
├── frames/
│   └── kf_001_0.000s.jpg     ← 单帧，文件名带时间戳（需要细节时按需读）
└── keyframes.json            ← 尺寸 / 时长 / 帧率 / 每帧时间戳 / diff 分值
```

`--sheet-only` 模式下只留总览图，单帧走临时目录拼完即删，输出为 `<视频名>_overview.jpg`。

**总览图长什么样**：只有两样东西——关键帧网格（顺序 **左→右、上→下 = 时间顺序**），以及每格下方的标签 `#序号  时间戳(秒)`。**不印任何元数据条。**

**`keyframes.json` 关键字段**：

| 字段 | 含义 |
| --- | --- |
| `width` / `height` | 原视频尺寸 |
| `duration` / `duration_text` | 总时长（秒 / 可读文本） |
| `fps` | 帧率 |
| `keyframe_count` | 关键帧数量 |
| `overview` / `overviews` / `overview_count` | 首张路径 / 全部路径列表 / 张数 |
| `keyframes[]` | 每帧的 `n`（帧号）、`time`（时间戳）、`path`（图片路径）、`diff`（差异分值） |

## 完整参数表

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `inputs` | — | 输入文件（视频 / GIF），可多个 |
| `-o, --output` | 见说明 | 输出位置。带 `--sheet-only` 时默认视频同目录，否则是 `<文件名>_keyframes/`；多个输入时 `-o` 失效 |
| `--sheet-only` | 关 | **只输出总览图**，不留单帧图片和 JSON |
| `--sheet-width` | `9600` | 总览图目标宽度。**给模型读时务必降到 1600~2400** |
| `--cell-width` | `0` | 直接指定每格宽度（px），0 = 按 `--sheet-width` 反算 |
| `--sheet-quality` | `95` | 总览图 JPEG 质量（始终 4:4:4 不抽样色度） |
| `--sheet-max-cells` | `32` | **每张图最多几格**，超了自动分到下一张（0 = 不限制）。给模型读时设 12 |
| `--sheet-max-sheets` | `4` | **最多生成几张图**；帧数超过 `张数 × 每张上限` 时按时间均匀抽稀 |
| `--cols` | `0` | 列数，默认自动取「整图最接近正方形」的网格（**给模型读时固定 3~4**） |
| `-t, --threshold` | `0`（自动） | 画面变化判定阈值 0~1，越大越严格。**一般不要改** |
| `--noise-k` | `4.0` | 自动阈值的灵敏度倍数，越小抽得越多 |
| `--min-time` | `0.30` | 相邻关键帧最小间隔（秒），防瞬间抖动炸出一堆帧 |
| `--motion-time` | `1.5` | 画面持续变化时强制抽帧的间隔（秒） |
| `--max-frames` | `200` | 最多保留多少关键帧，超了按时间均匀抽稀 |
| `--max-width` | `0` | 单帧图片最大宽度，`0` = 保持原尺寸（拼图最清晰） |
| `--quality` | `92` | 单帧 JPEG 质量 |
| `--format` | `jpg` | 单帧格式，`jpg` / `png` |
| `--no-contact-sheet` | 关 | 不生成总览图（只存单帧） |
| `--include-last` | 关 | 额外保留最后一帧 |
| `--json` | 关 | 只输出 JSON，便于程序调用 |
| `-q, --quiet` | 关 | 不打印进度 |

## 工作原理

### 1. 差异检测：双角度看变化

每帧缩成 200px 宽灰度小图，与上一帧求差异，**同时看两个角度、取较大值**：

- **全局平均差异** —— 整屏变化（转场、换色）
- **8×8 分块中"变化最剧烈那一块"的差异** —— 局部小动作

> 只盯全局平均的话，角落一个小物体移动会被大量没变的像素稀释掉，实测差异只有 `0.004`、和噪声一个量级；看分块能拿到 `0.06`，区分度干净得多。

### 2. 自适应阈值：为什么不用手动调

视频里大部分时间画面静止，所以"相邻帧差异"的中位数约等于**底噪**（压缩噪点、轻微抖动）。

```
阈值 = 底噪 × --noise-k，夹在 [0.008, 0.08] 之间
```

- 完全静止的合成动画：底噪 ≈ 0 → 阈值 = 0.008（很敏感）
- 有噪点的实拍视频：底噪 ≈ 0.011 → 阈值 ≈ 0.043（不被噪点骗）

差异分数量级参考：

| 分数 | 含义 |
| --- | --- |
| `< 0.005` | 噪声 / 几乎没变 |
| `0.01 ~ 0.05` | 局部小变化（角落出字幕、小图标动） |
| `> 0.1` | 明显变化（整屏换色、转场、大幅运动） |

**抽得太多时，请优先用 `--sheet-max-cells` / `--max-frames` 抽稀，不要调高阈值。** 抽稀是在已经选好的好帧里均匀挑，画面质量不受影响；而调高阈值有坑——元素淡入淡出这类渐进动画不再被当成"变化"，算法会在动画中途误判成"变化已结束"，抽到元素还没出现 / 已经消失的**空白中间态**。

实测同一段 3 分钟讲解视频：

| 阈值 | 结果 |
| --- | --- |
| `0.008`（默认自动） | 134 帧，每帧都有完整内容 ✅ |
| `0.03` | 19 帧，一多半是空白画面 ❌ |
| `0.008` + 抽稀到 32 格 | 每格仍是完整画面，标题可读 ✅ |

### 3. 选帧规则

- 第一帧一定保留
- 画面变了不急着选，**等它变完**——变化结束后稳定下来的帧才是"完整展示"画面
- 画面持续在变（运镜、长动效）就每 `--motion-time` 秒补一张，免得整段运动只出一张图
- 相邻关键帧至少隔 `--min-time` 秒
- 到片尾还在变就补上结尾画面
- 帧数极少的短 GIF（≤8 帧）全部保留

### 4. 导出与拼图

再完整解码一遍视频，命中帧号就存图。**没有**用 ffmpeg 的 `select='eq(n,0)+eq(n,17)+...'` 滤镜——关键帧上百个后那个表达式会超出 ffmpeg 解析器上限直接报错，改成 Python 侧按帧号筛选，只解一遍。

拼图用网格排布 + LANCZOS 重采样，存 JPEG 开 4:4:4，保证格子里的文字不糊。

### 5. 分张策略

先把帧均匀抽稀到 `sheet_max_sheets × min(sheet_max_cells, 16)` 以内，再**尽量平均**地切成若干张（每张格数差 ≤ 1），保证每张清晰度一致、按时间顺序排列。

## 作为 AI Agent Skill 使用

**这一节就是「怎么把它接到多模态大模型上」的标准答案。** 本目录同时是一份 Agent Skill——这类 Agent 由具备视觉能力的多模态模型驱动，配套的 `SKILL.md` 把「抽帧 → 逐张读图 → 补读单帧 → 输出理解」整条链路固化下来，可被自动调用。核心三条约定：

1. **隐式调用铁律** —— 对话里只要出现视频 / GIF 文件（上传附件、`@` 引用、给出本地路径），无论用户是否明说"分析这个视频"，都要先抽帧识图再作答。禁止不抽帧就凭文件名猜内容。
2. **固定档位** —— 一律 `--cols 3 --sheet-max-cells 12 --sheet-width 1600`，输出到会话工作目录下的 `video_understanding/<视频名>/`，不要落在用户原始素材目录。
3. **逐张读完** —— 关键帧多时会分多张总览图，按 JSON 里 `overviews` 的顺序**一张一张全部读完**；小字读不清时按 `keyframes.json` 的帧号去 `Read` 单帧原图补细节，**不要重跑脚本**。

识图后输出的是一段**自然语言理解**，而不是技术报告：

- **画面**：场景、主体、动作、镜头、光线、色调、氛围
- **文字**：画面上出现的所有字——标题、字幕、贴纸、图表标注、界面文案，读懂并写出原文关键句
- **合起来**：画面 + 文字共同讲了什么 / 表达什么

**输出里不写时间轴、不写时间戳、不写分辨率/时长/帧率。**

> **边界**：本技能只做**画面内容理解**（画面 + 屏幕文字）。**音频内容（人声说了什么）不在覆盖范围内**——需要语音转写时另行处理，不要假装从画面上"听"到了内容。只抽帧，不改视频，不会为了"看得更清"去转码或剪裁你的原始素材。

### 不在 Agent 里？自己接多模态 API 也一样

没有 Agent 环境时，用同样的三段式接你自己的多模态模型即可：

```python
from extract_keyframes import extract_keyframes

# 1. 前处理：抽帧 + 拼图（本工具，不调用任何模型）
meta = extract_keyframes(
```

## 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 能用纯文本模型跑吗？ | **不能。** 产出全是图片，必须交给**具备视觉能力的多模态大模型**；纯文本模型拿不到任何画面信息 |
| 它能直接给出"这段视频讲了什么"吗？ | 不能。脚本只产图和 JSON，**语义结论全部由多模态大模型给出**——它是前处理层，不是理解层 |
| 读图返回 `[Image too large]` | 图超尺寸。把 `--sheet-width` 降到 2400 以内，并确认 `--cols ≤ 4` |
| 总览图里字糊、读不出 | **一张里格子太多**。把 `--sheet-max-cells` 降到 12（脚本会自动分多张），或直接 `Read` 单帧 |
| 出了多张 `overview`，漏读后几张 | 正常，关键帧多就会分张。按 JSON 里 `overviews` 列表**逐张读完**，顺序 = 时间顺序 |
| 路径含空格 / 中文报错 | 命令里的路径必须加引号 |
| 抽出来的帧是空白画面 | 曾手动调高 `--threshold`。**恢复自动阈值**（不传或传 0），要减少数量用 `--sheet-max-cells` / `--max-frames` 抽稀 |
| 找不到 ffmpeg | 脚本内置多处兜底路径；仍失败才需要手动安装 ffmpeg |
| GIF 只抽出几帧 | 正常，≤8 帧的短 GIF 脚本会全部保留 |
| 输出散落在视频旁边 | 没传 `-o`。显式指定 `-o <输出目录>` |

调参细节、阈值原理、算法与性能数据见 [`references/parameters.md`](references/parameters.md)。
